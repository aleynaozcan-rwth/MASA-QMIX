# Validation Chapter: Understanding MASA-QMIX System Convergence

## Chapter Overview

This chapter presents a comprehensive validation methodology for evaluating the convergence and stability of the MASA-QMIX multi-agent reinforcement learning system. The validation framework is structured around understanding what metrics truly indicate about system behavior, their expected ranges in QMIX architecture, and critical pitfalls in interpretation.

---

## 1. Understanding the MASA-QMIX Training Process

### 1.1 How the System Learns

The MASA-QMIX system employs value-based multi-agent reinforcement learning where:

1. **Individual agents** learn Q-values representing expected future rewards
2. **Mixing network** combines individual Q-values into a joint team Q-value (Q_tot)
3. **TD-learning** updates Q-values based on Temporal Difference errors: `TD-error = Q_target - Q_current`
4. **Policy extraction** uses ε-greedy selection based on Q-values

### 1.2 The QMIX Value Decomposition Property

**Critical constraint**: QMIX enforces monotonicity: `∂Q_tot/∂Q_i ≥ 0`

This means:
- Individual Q-values must positively contribute to team Q-value (∂Q_tot/∂Q_i ≥ 0)
- **Q-values can be negative** - there is no sign constraint in QMIX
- The mixing network uses non-negative weights generated by hypernetworks
- **What matters**: Magnitude scale consistency with rewards, not the sign

### 1.3 Reward Scale Context

For proper Q-value interpretation, we must establish reward scale:
- Per-step reward range: -0.17 to 1.34 (mean: ~0.5)
- Episode cumulative rewards: 4.7 to 39.3 (mean: ~25.6)
- Discount factor γ = 0.99, average episode length T ≈ 70

**Theoretical Q-value calculation**:
```
Discounted return = Σ(γ^t × r_t) for t=0 to T
For constant reward r and finite horizon:
Q_expected ≈ r × [(1 - γ^T) / (1 - γ)] ≈ 0.5 × 50.52 ≈ 25
```

**Key insight**: Q-values should converge to values with **magnitude comparable to** episode returns (~18-30 range). The sign can be negative depending on the reward structure.

## 2. Metric Categories and Their Meanings

Convergence metrics naturally group into three categories, each revealing different aspects of system health.

### 2.1 **Learning Stability Indicators**

**Purpose**: Assess whether the learning process is numerically stable and the value function is converging.

#### TD Error (Temporal Difference Error)
```
TD_error = R + γ × Q_target(s', a') - Q_current(s, a)
```

**What it represents**:
- Prediction error: how wrong the current Q-estimate is
- Should decrease as Q-values become more accurate
- Measures consistency between current and target networks

**Expected behavior**:
- ✅ **Initial**: Moderate to high (50-200) as Q-values are random
- ✅ **Mid-training**: Gradual decrease as predictions improve
- ✅ **Convergence**: Low and stable (< 50)

**Warning signs**:
- ❌ **Increasing TD error**: Value function diverging, not converging
- ❌ **Persistently high**: Q-values not learning meaningful predictions
- ⚠️ **Very low too early**: May indicate pessimistic/optimistic bias

**Why TD error alone is misleading**:
1. **Low TD error ≠ Good performance**: Agents can learn consistent but suboptimal policies
2. **Pessimistic convergence**: TD error can be low because Q-values underestimate returns uniformly
3. **Degenerate solutions**: All Q-values converging to similar values (no discrimination)

**Example pathology**: TD error drops to 10 (appears converged) but Q-values are all negative while rewards are positive - the system has converged to the wrong solution.

---

#### Loss Function (MSE of TD error)
```
Loss = E[(TD_error)²]
```

**What it represents**:
- Squared magnitude of prediction errors
- Direct optimization target for Q-network
- Gradient magnitude indicator

**Expected behavior**:
- ✅ **Initial**: High (100-10,000) depending on reward scale
- ✅ **Mid-training**: Exponential decay with occasional spikes
- ✅ **Convergence**: Low and stable (< 100)

**Warning signs**:
- ❌ **Loss explosions**: Values > 1,000,000 indicate gradient explosion
- ❌ **Oscillating loss**: Instability in learning rate or target network updates
- ❌ **Plateau at high values**: Network capacity or learning issues

**Why loss alone is misleading**:
1. **Scale dependent**: Loss magnitude depends on Q-value scale (if Q ~ 1000, loss can be huge)
2. **Local minima**: Loss can decrease while policy quality degrades
3. **Overfitting to batch**: Low training loss doesn't guarantee good episodic performance

**Critical correlation**: Loss should decrease **together with** TD error. If loss is low but TD error is high, the network is overfitting to noise.

---

### 2.2 **Performance Indicators**

**Purpose**: Measure actual task performance and learning progress.

#### Episode Reward
```
R_episode = Σ(r_t) for all timesteps in episode
```

**What it represents**:
- Cumulative task-specific rewards
- Direct measure of policy quality
- What we ultimately care about

**Expected behavior in QMIX**:
- ✅ **Initial**: Variable, often poor (near random policy)
- ✅ **Early training**: Rapid improvement as obvious patterns learned
- ✅ **Mid-training**: Slower improvement, discovering complex strategies
- ✅ **Convergence**: High with low variance (stable optimal policy)

**Warning signs**:
- ❌ **Decreasing rewards over time**: Catastrophic forgetting or Q-value divergence
- ❌ **High variance late in training**: Policy instability
- ❌ **No improvement**: Credit assignment failure or exploration issues

**Why episode reward alone is misleading**:
1. **Variance masking trends**: Single episodes can be lucky/unlucky
2. **Stochastic environments**: Reward variance may be inherent, not learned
3. **Delayed improvement**: Reward may plateau while internal representations improve
4. **Exploration tradeoff**: High ε causes reward suppression despite good Q-values

**Best practice**: Always use moving average (50-100 episodes) and track variance:
```
Reward_MA(t) = mean(Rewards[t-50:t])
Stability = std(Rewards[t-50:t]) / |Reward_MA(t)|  # Coefficient of variation
```

---

#### Batch Reward (Training Batch Average)
```
R_batch = mean(r_t) for transitions in replay buffer batch
```

**What it represents**:
- Average immediate reward in sampled experiences
- Quality of experiences in replay buffer
- Differs from episode reward (immediate vs. cumulative)

**Expected behavior**:
- ✅ **Stable range**: Should reflect environment's reward distribution
- ✅ **Slight increase**: If policy improves, samples shift to better states
- ✅ **Correlation with episode reward**: Should track episode reward trends

**Warning signs**:
- ❌ **Divergence from episode reward**: Replay buffer not representative
- ❌ **Decreasing batch reward**: May indicate exploration collapse

**Why batch reward alone is misleading**:
1. **Replay buffer bias**: Old experiences from poor policies persist
2. **Not episode-level**: High per-step reward doesn't guarantee episode success
3. **Sample distribution shift**: As policy changes, batch statistics change

---

### 2.3 **Value Function Quality Indicators**

**Purpose**: Assess whether Q-values accurately represent true returns and enable good decisions.

#### Q-Values (Individual Agent Q-estimates)
```
Q_i(s, a_i) = E[R_future | s, a_i, π]
```

**What it represents**:
- Agent's estimate of expected future discounted return
- Decision-making basis for action selection
- Should converge to true value function V*(s)

**Expected behavior in QMIX**:
- ✅ **Initial**: Near zero (random initialization) or small random values
- ✅ **Early training**: Adjust as agents discover reward structure
- ✅ **Mid-training**: Stabilize in magnitude comparable to episode returns
- ✅ **Convergence**: |Q-values| ≈ |episode returns| in scale
  - For our system: Expected |Q| magnitude ~ **18-30 range**

**Critical in QMIX**: Q-values have no sign constraint - they can be negative. What matters is **magnitude consistency with rewards**.

**Warning signs**:
- ❌ **Magnitude divergence**: |Q-values| >> |episode returns| (e.g., |Q| = 5000 when |rewards| ~ 25)
- ❌ **Monotonic divergence**: Q-values continuously decrease/increase without stabilizing
- ❌ **Explosive growth**: Q magnitude growing unbounded (|Q| → ∞)
- ⚠️ **Scale inconsistency**: Q magnitude > 10x episode return magnitude

**Why Q-values alone are misleading**:
1. **Scale ambiguity**: Without reward context, can't judge if Q = 100 is reasonable
2. **Bias-variance tradeoff**: Biased Q-values can still produce good policies
3. **QMIX amplification**: Mixing network can amplify individual Q-value errors non-linearly
4. **Monotonicity constraint**: Individual Q-values constrained by mixing, may not match true individual values

**Critical diagnostic**: Compare Q-value magnitude to episode return magnitude:
```
Q_magnitude_ratio = |mean(Q-values)| / |mean(episode_rewards)|

✅ Healthy: 0.5 < ratio < 2.0 (Q magnitude matches reward scale)
⚠️ Warning: 2.0 < ratio < 10 (Moderate scale mismatch, monitor)
❌ Critical: ratio > 10 (Severe divergence, likely to cause instability)

Note: Sign is irrelevant - Q can be negative even with positive rewards.
```

---

#### Gradient Norms (If tracked)
```
gradient_norm = ||∇θ Loss||₂
```

**What it represents**:
- Magnitude of parameter updates
- Learning dynamics indicator
- Stability metric

**Expected behavior**:
- ✅ **Initial**: Moderate (1-100)
- ✅ **Training**: Gradual decrease as loss decreases
- ✅ **With clipping**: Bounded to max_norm (typically 10)

**Warning signs**:
- ❌ **Exploding gradients**: Norms > 1000
- ❌ **Vanishing gradients**: Norms < 0.001

## 3. Cross-Metric Validation Framework

**Key principle**: No single metric is sufficient. Convergence requires consistent signals across all categories.

### 3.1 Convergence Checklist

| Metric | Healthy Convergence | Warning Signs | Critical Issues |
|--------|-------------------|---------------|----------------|
| **TD Error** | Decreasing, stabilizes < 50 | Plateaus high (>200) | Increasing over time |
| **Loss** | Decreasing, stabilizes < 100 | Oscillations, spikes | Explosions (>10⁶) |
| **Episode Reward** | Increasing, low final variance | High variance, plateau | Decreasing over time |
| **Batch Reward** | Stable, tracks episode reward | Diverges from episodes | Decreasing significantly |
| **Q-Values** | |Q| magnitude matches |rewards| | |Q| 2-10x |reward| magnitude | |Q| > 10x |reward| (divergence) |
| **Epsilon** | Decays smoothly to minimum | - | Stuck at high values |

### 3.2 Diagnostic Scenarios

#### Scenario 1: "False Convergence - Pessimistic Bias"
- ✅ TD error: Low (15)
- ✅ Loss: Low (50)
- ❌ Episode reward: Poor and decreasing
- ❌ Q-values: All negative, uniform

**Interpretation**: System converged to suboptimal degenerate solution. Q-values learned to consistently underestimate, minimizing TD error but not maximizing reward.

**Root cause**: Credit assignment failure, insufficient exploration, or reward scale issues.

---

#### Scenario 2: "Q-Value Explosion"
- ❌ TD error: Increasing (50 → 500)
- ❌ Loss: Exploding (1000 → 1,000,000)
- ❌ Episode reward: Degrading
- ❌ Q-values: Magnitude diverging (|Q|: 10 → 5000+)

**Interpretation**: Catastrophic divergence. Mixing network creating positive feedback loop: high |Q| → high TD-error → high loss → larger gradient updates → worse Q-values. The problem is the **magnitude divergence** (200x reward scale), not the sign.

**Root cause**: Missing gradient clipping, inappropriate learning rate, or QMIX hypernetwork instability.

---

#### Scenario 3: "Healthy Learning"
- ✅ TD error: Decreasing (200 → 30)
- ✅ Loss: Decreasing (5000 → 80)
- ✅ Episode reward: Increasing (10 → 35), variance decreasing
- ✅ Q-values: |Q| stabilizing around 20-25 (magnitude matches episode returns)

**Interpretation**: Normal convergence. All metrics aligned, indicating stable learning of good policy.

---

#### Scenario 4: "Overfitting/Exploration Collapse"
- ✅ TD error: Low (20)
- ✅ Loss: Low (60)
- ❌ Episode reward: Stuck at suboptimal value with zero variance
- ⚠️ Q-values: Stable but lower than episode potential

**Interpretation**: Converged to local optimum. Policy is consistent (low TD error) but not exploring better strategies.

**Root cause**: Epsilon decayed too fast, or reward structure encourages safe suboptimal behavior.

## 4. Why Single Metrics Are Insufficient

### 4.1 The TD Error Paradox

**Common misunderstanding**: "TD error is low, so the system converged."

**Reality**: TD error measures **consistency**, not **correctness**.

**Example pathologies**:

1. **Uniform underestimation**:
   - All Q-values learn to be -100
   - All TD errors become near zero (consistent)
   - But policy is random (all actions equally bad)

2. **Pessimistic convergence**:
   - Agent learns Q-values systematically below true returns
   - TD error low because current and target both pessimistic
   - Reward never improves beyond initial random policy

3. **Biased target network**:
   - If target network is frozen with wrong values
   - Current network converges to match wrong target
   - Low TD error, terrible performance

**Validation requirement**: Low TD error must be accompanied by:
- Q-values in expected range (matching episode returns)
- Increasing episode rewards
- Low loss

### 4.2 The Reward Plateau Problem

**Common misunderstanding**: "Rewards aren't improving, training failed."

**Reality**: Reward improvement has complex dynamics.

**Legitimate reasons for reward plateau**:

1. **Exploration-exploitation tradeoff**:
   - High epsilon (ε > 0.3) suppresses reward despite good Q-values
   - Necessary for finding better strategies
   - Reward improves after epsilon decays

2. **Internal representation learning**:
   - Q-values becoming more accurate (TD error decreasing)
   - Policy not yet exploiting improved values
   - Reward jumps once threshold reached

3. **Local optimum near global**:
   - System found 80% optimal strategy quickly
   - Last 20% requires extensive exploration
   - Appears as long plateau before final improvement

**Validation requirement**: Reward plateau acceptable only if:
- TD error still decreasing (learning ongoing)
- Q-values stabilizing (not diverging)
- Variance decreasing (policy becoming more deterministic)

### 4.3 The Q-Value Scale Ambiguity

**Common misunderstanding**: "Q-values are increasing, system is learning."

**Reality**: Q-value magnitude must be contextualized.

**Why Q-value magnitude matters**:

1. **Overestimation cascade (QMIX-specific)**:
   ```
   Individual Q: |Q_i| = 100 (should be ~25 in magnitude)
   Mixing amplification: Q_tot = Σ(w_i × Q_i) where w_i > 0
   If 5 agents: |Q_tot| = 500 (should be ~125 in magnitude)
   Next iteration: TD error grows → Loss grows → Updates grow
   Further divergence: |Q| grows to 600, 800, 1000...
   ```

2. **Action selection consistency**:
   - Q-values can be negative, argmax(Q) still works correctly
   - What matters: Q-values distinguish between actions consistently
   - Problem: If all Q-values collapse to similar values (uniform)

3. **Divergence detection**:
   ```python
   # Calculate expected Q-value range
   avg_episode_reward = 25.0
   avg_episode_length = 70.0
   discount_factor = 0.99
   
   geometric_sum = (1 - discount_factor**avg_episode_length) / (1 - discount_factor)
   expected_Q = (avg_episode_reward / avg_episode_length) * geometric_sum
   # expected_Q ≈ 18-25
   
   # Check divergence
   actual_Q = mean(q_values)
   divergence_factor = abs(actual_Q) / expected_Q
   
   if divergence_factor > 10:
       print("CRITICAL: Q-value divergence")
   ```

**Validation requirement**: Q-values must be:
- Similar magnitude to episode returns (±2x tolerance)
- Same sign as predominant rewards
- Stabilizing, not monotonically diverging

## 5. Expected Behaviors in QMIX Architecture

### 5.1 Q-Value Characteristics

**Theoretical properties**:
- Individual Q-values: Can be any real number (ℝ) - no sign constraint
- Mixed Q-value (Q_tot): Monotonic in individual Q-values (∂Q_tot/∂Q_i ≥ 0)
- **Important**: Sign is not constrained, magnitude scale is what matters

**Expected magnitude ranges** (for our system with |rewards| ~25/episode):
- ✅ **Healthy**: |Q| ∈ [10, 50] (within 2x of episode return magnitude)
- ⚠️ **Tolerable**: |Q| ∈ [50, 250] (moderate scale mismatch)
- ❌ **Severe divergence**: |Q| > 250 (10x+ divergence, likely instability)

**QMIX-specific considerations**:
- Mixing network can amplify: Small individual errors → large team Q errors
- Monotonicity constraint: Limits correction of overestimation
- Hypernetwork sensitivity: State-dependent mixing weights can be unstable

### 5.2 Loss Dynamics

**Expected progression**:
```
Episodes 0-100:   Loss ~ 1000-10000 (high initial error)
Episodes 100-300: Loss ~ 100-1000  (rapid learning)
Episodes 300-600: Loss ~ 50-200    (refinement)
Episodes 600+:    Loss ~ 10-100    (convergence)
```

**QMIX loss is MSE of TD error**:
```
Loss = E[(R + γ × Q_target_tot - Q_current_tot)²]
```

If Q-values are ~25 and TD error ~50:
```
Loss ≈ 50² = 2500 (expected)
```

If Q-values diverge to -5000 and TD error ~500:
```
Loss ≈ 500² = 250,000 (divergence)
```

**Acceptable loss range**:
- ✅ **Converging**: Loss < (expected_Q_range)²
- For Q ~ 25: Loss < 625 is healthy
- ⚠️ **Warning**: Loss > 10,000 sustained
- ❌ **Critical**: Loss > 100,000 or increasing

### 5.3 TD Error Evolution

**Theoretical trajectory**:
```
Initial: |TD error| ≈ |Q_target - Q_random| ≈ Q_target ≈ 20-30
Mid-training: |TD error| decreases as Q_current → Q_target
Convergence: |TD error| ≈ reward variance ≈ 5-15
```

**Why TD error doesn't reach zero**:
1. Stochastic rewards: Inherent variance in R
2. Function approximation: Neural network can't perfectly represent Q*
3. Moving target: Target network updates prevent exact matching
4. Exploration: ε-greedy introduces off-policy data

**Expected ranges**:
- ✅ **Initial**: |TD error| ~ 50-200
- ✅ **Mid-training**: |TD error| ~ 20-100
- ✅ **Convergence**: |TD error| ~ 10-50
- ❌ **Divergence**: |TD error| increasing or > 500

### 6.2 Cross-Group Validation Logic

**Validation Rule 1: Stability + Performance Agreement**
```
IF (TD error decreasing AND Loss decreasing)  # Stability good
   AND (Episode reward NOT increasing)        # Performance poor
THEN:
   → False convergence to suboptimal policy
   → Check: Q-value uniformity, exploration level
```

**Validation Rule 2: Q-Value Magnitude Check**
```
IF (|Q-values| >> |Episode rewards|)  # e.g., |Q|=1000, |Reward|=25
   OR (|Q| magnitude growing unbounded)
THEN:
   → Value function divergence
   → Check: Mixing network weights, gradient clipping
   → Expected: Stability metrics (TD error, Loss) also exploding

Note: Q being negative is not a problem by itself.
```

**Validation Rule 3: Exploration-Performance Decoupling**
```
IF (Epsilon high, e.g., >0.3)
   AND (Episode reward low/variable)
   BUT (Q-values reasonable AND TD error decreasing)
THEN:
   → Exploration suppressing performance (normal)
   → Wait for epsilon decay
   → Expected: Reward improvement when epsilon < 0.2
```

**Validation Rule 4: Complete Convergence**
```
ALL of the following must be TRUE:
✓ TD error < 50 and stable
✓ Loss < 100 and stable
✓ Episode reward increasing or at optimum
✓ Reward variance decreasing
✓ |Q-values| magnitude matches |episode returns| (0.5x to 2x range)
✓ Epsilon at minimum (0.05-0.1)

THEN: Successful convergence
```

1. TD error < 50: Indicates good value prediction

### 7.2 Validation Metrics

**Quantitative Convergence Score**:
```python
def convergence_score(metrics):
    """
    Returns score 0-100 indicating convergence quality
    """
    score = 0
    
    # Stability (40 points)
    if metrics['td_error'] < 50:
        score += 20
    elif metrics['td_error'] < 100:
        score += 10
    
    if metrics['loss'] < 100:
        score += 20
    elif metrics['loss'] < 1000:
        score += 10
    
    # Performance (40 points)
    reward_improvement = (metrics['reward_final'] - metrics['reward_initial']) / abs(metrics['reward_initial'])
    score += min(20, reward_improvement * 100)  # Up to 20 points
    
    reward_cv = metrics['reward_std'] / abs(metrics['reward_mean'])
    if reward_cv < 0.2:
        score += 20
    elif reward_cv < 0.4:
        score += 10
    
    # Q-value quality (20 points)
    q_ratio = abs(metrics['q_value_mean']) / metrics['reward_mean']
    if 0.5 < q_ratio < 2.0:
        score += 20
    elif 0.2 < q_ratio < 5.0:
        score += 10
    
    return score

# Interpretation:
# 80-100: Excellent convergence
# 60-79:  Good convergence
# 40-59:  Partial convergence
# 20-39:  Poor convergence
# 0-19:   Failed convergence
```

## 8. Theoretical Foundation: Q-Value Sign and Magnitude

**Important clarification for academic rigor**:

> In value-based multi-agent reinforcement learning, **Q-values are not constrained to be positive** and may take negative values depending on the reward structure and discounting. Convergence is therefore not assessed based on the absolute magnitude or sign of Q-values, but on their **stabilisation and consistency** over training. A decreasing or negative Q-value trend does not necessarily indicate poor learning, provided that the value estimates converge and remain numerically stable.

**QMIX-specific theoretical properties**:

1. **Monotonicity constraint** (Rashid et al., 2018):
   - QMIX enforces: ∂Q_tot/∂Q_i ≥ 0 for all agents i
   - This ensures individual Q-values positively contribute to joint action-value
   - **No sign constraint**: Q_i ∈ ℝ (can be negative)

2. **What matters for convergence**:
   - ✅ **Magnitude consistency**: |Q| should scale with |episode returns|
   - ✅ **Stability**: Q-values should converge, not diverge
   - ✅ **Discriminability**: Q-values should distinguish between actions
   - ❌ **Sign**: Positive/negative Q is not an indicator of convergence quality

3. **When negative Q-values are expected**:
   - Penalty-dominant reward structures (e.g., cost minimization)
   - Long-term discounting of small positive rewards with immediate costs
   - Baseline-adjusted rewards (common in policy gradient methods)

**Divergence vs. convergence**:
- **Convergence**: Q-values stabilize at any level (positive or negative)
- **Divergence**: |Q| grows unbounded or oscillates without stabilizing

## 9. Conclusion: Multi-Metric Validation Philosophy

**Key takeaway**: Convergence in multi-agent reinforcement learning is not determined by any single metric, but by the **consistent alignment of stability, performance, and value quality indicators**.

**Essential validation principles**:

1. **No metric in isolation**: TD error, loss, rewards, and Q-values must all tell a consistent story

2. **Context is critical**: Q-value magnitude must be compared to episode return magnitude; sign is not diagnostic

3. **Temporal consistency**: Metrics should show clear trends (stabilizing/converging), not unbounded growth

4. **Architecture awareness**: QMIX's mixing network introduces unique behaviors (amplification, monotonicity constraints)

5. **Failure mode recognition**: Know the difference between:
   - False convergence (low TD error, poor performance)
   - **Q-value divergence (magnitude >> reward scale, unbounded growth)** - not about sign
   - Exploration artifacts (temporarily suppressed rewards)
   - True convergence (all metrics aligned)

6. **Proactive monitoring**: Check cross-metric relationships at each training phase, don't wait until the end

**This validation framework enables robust assessment of whether MASA-QMIX has learned an effective scheduling policy or merely achieved numerical artifacts of optimization.**

```
│           ├─ TD error/Loss increasing → Divergence → Add grad clip
│           ├─ Rewards not improving → False convergence → Check Q-values
│           └─ Q-values diverging → QMIX instability → Reduce LR
│
└─ Cross-check: Do metrics agree?
   ├─ YES → Trust the assessment
   └─ NO → Investigate inconsistency
           ├─ Stability good, performance poor → Exploration issue
           ├─ Performance good, stability poor → Unsustainable, will collapse
           └─ Q-values wrong scale → Value divergence
```

### A.3 Common Failure Signatures

| Failure Mode | TD Error | Loss | Reward | Q-Value | Diagnosis |
|--------------|----------|------|--------|---------|-----------|
| **Gradient Explosion** | ↑↑ | ↑↑↑ | ↓ | ↑↑ or ↓↓ | No gradient clipping |
| **False Convergence** | ↓ | ↓ | → or ↓ | ≈0 | Degenerate uniform Q |
| **Q-Overestimation** | ↑ | ↑ | → | ↑↑ | QMIX amplification |
| **Q-Divergence (your case)** | ↑ | ↑↑↑ | ↓ | Magnitude ↑↑ | No gradient clipping |
| **Exploration Collapse** | ↓ | ↓ | → | ↓ | Epsilon too low early |
| **Healthy Convergence** | ↓ | ↓ | ↑ | Stable magnitude | All aligned ✅ |

**Legend**: ↑ increasing, ↓ decreasing, → stable, ↑↑ rapidly increasing, ↑↑↑ exploding

**Critical note**: Q-value sign (positive/negative) is NOT a failure indicator. Only magnitude divergence matters.
